## 1. データ契約(3リポ共通)

`chart.events[]` に `timesig` イベントを追加(サーバー配信 JSON は snake_case):

```json
{ "type": "timesig", "time_ms": 12345, "numerator": 7, "denominator": 8 }
```

- `time_ms` = その拍子が始まる**小節の頭(バーライン起点)**。複数置ける。
- `numerator` = 1 小節の拍数、`denominator` = 1 拍の音価(4=四分, 8=八分)。
- `timesig` が 1 つも無ければ**全編 4/4**。最初の `timesig` 以前も 4/4。`bpm` 変化と独立。
- 既存 seed 譜面(全て 4/4・timesig 無し)は形式上は不変だが、下記②の密度変更でスコアは変わる。

## 2. 小節長・ホールド tick の公式(最重要・全実装一致)

時刻 t の実効 bpm・拍子で:

```
quarterMs(t)          = 60000 / bpm(t)
measureMs(t)          = quarterMs(t) * numerator(t) * (4 / denominator(t))
holdTickIntervalMs(t) = measureMs(t) / 8        // ★ HoldTicksPerMeasure = 8(旧 2)
```

例(bpm=120, quarterMs=500):

| 拍子 | measureMs | tick間隔 |
|---|---|---|
| 4/4 | 2000 | 250 |
| 3/4 | 1500 | 187.5 |
| 6/8 | 1500 | 187.5 |
| 7/8 | 1750 | 218.75 |

tick 生成ループ(間隔だけが拍子・密度依存に変わる。他は不変):

```
cursor = startMs
loop:
  cursor += holdTickIntervalMs(cursor)
  if cursor >= endMs - HoldTailGuardMs: break    // HoldTailGuardMs = 1.0(不変)
  emit tick at cursor
```

`bpm(t)`/`numerator(t)`/`denominator(t)` は**その時刻以前の最後の該当イベント**(時刻昇順、
無ければ bpm=120 / 4/4)。クライアントと完全に同じサンプリングにすること。

- 4/4・120bpm で tick 間隔 1000ms → **250ms**(八分音符刻み)。4/4 含む全譜面で tick 数が増える。
- `total_notes`(= 採点イベント総数 = Σ tap + ホールドごとに head+ticks+tail)はクライアントが
  **ロード時に再計算**するので JSON 改変は不要。Go も同じ数え方なら自動追従。
- 満点(1,000,000)は `total_notes` 由来なので tick が増えても **1,000,000 のまま**。

## 3. ホールド「復帰」+ 復帰後 Great(②の判定仕様)

**旧**: 離してガード(50ms)を超えると放棄(残り tick を全部 Miss・回復不能)。
**新**: 放棄しない。離している間の tick は Miss(コンボ断)だが、**押し直せば継続**。復帰後の
**最初の1判定(tick または尾)だけ Great**、以降は通常通り PerfectPlus。

### 状態機械(クライアント `HoldJudgmentTracker` と完全一致させること)
状態: `isHeld`, `lastReleaseMs`(無し=-1), `recovering`, `headJudged`, `tailJudged`, `abandoned`。
定数 `GUARD_MS = 50`。

- **離上(release, time)**: `headJudged && !abandoned` のとき `isHeld=false; lastReleaseMs=time`。
- **再押下(press, time)**: `headJudged && !abandoned` のとき
  - `!isHeld && lastReleaseMs>=0 && (time - lastReleaseMs) > GUARD_MS` なら `recovering=true`。
  - その後 `isHeld=true; lastReleaseMs=-1`。(ガード内の押し直しは復帰扱いせず無ペナルティ)
- **各 tick(時刻 tickTime, `headJudged && !abandoned` のときのみ進行)**:
  - `isHeld`: `recovering` なら **Great**(→`recovering=false`)、でなければ **PerfectPlus**。
  - `!isHeld`: `sinceRelease = tickTime - lastReleaseMs`(lastReleaseMs<0 は 0 扱い)。
    `sinceRelease <= GUARD_MS` → **PerfectPlus**、超 → **Miss**(放棄しない)。
- **尾(tail, currentMs>=endMs の最初の解決)**:
  - `isHeld`: `recovering` なら **Great**(→`recovering=false`)、でなければ **PerfectPlus**。
  - `!isHeld`: `sinceRelease = endMs - lastReleaseMs`。`<=GUARD_MS` → PerfectPlus、超 → Miss。
- **ヘッド未ヒットの放棄(abandoned)** は従来通り(頭の Good 窓を逃したらそのホールドは死亡)。
  ガード超の離上で abandoned にしない点だけが変更。

### 判定スコア重み(既存・不変)
PerfectPlus/Perfect = 1.0、**Great = 199/200**、Good = 3/4、Miss = 0。
コンボ境界 = Good なので Great は継続・Miss は断。tiebreak(Σ 2×PerfectPlus + 1×Perfect)に
Great は寄与 0。

## 4. パリティ検証(golden vector)

`testdata/replay_vectors/` 形式に新規ケースを追加して突き合わせたい:

- **ホールド密度**: 長いホールドで tick 数(= `total_notes`)が /8 で一致するか。
- **復帰**: 途中で離して押し直すケース。`PerfectPlus`/`Great`/`Miss` の各カウント・`Score`・
  `x_micro`・`total_notes` が一致するか(**復帰直後だけ Great** が肝)。
- **変拍子**: 3/4 のみ / 6/8 のみ / 途中 4/4→7/8 / ホールド跨ぎ。

各ケースで `Score`・`x_micro`・`total_notes`・`PerfectPlusCount`/`GreatCount`/`MissCount` が
クライアント(本体 Domain)と一致すること。**期待値 JSON はこちらで出力して共有できます**。

実対戦中のライブ判定を1ノートずつ書き出す `JudgmentTrace`(既定オフ)も入れてあるので、
サーバー再判定ログとの delta 突き合わせ(P+ 16ms 境界含む全判定)に使えます。
